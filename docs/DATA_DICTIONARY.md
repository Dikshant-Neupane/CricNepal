# Data Dictionary and Provenance (plan task 1.4, criterion D6)

Created 2026-10-29 from the implementation audit's data inventory
(§2). For every dataset: content, source, licence as far as known,
how it was obtained, freshness at creation, and its role.

Licence position (whole project): no dataset in this repository
carries an explicit licence field. Ball-by-ball data originates from
cricsheet (cricsheet.org, which publishes its data for use with
attribution); scorecard captures are transcribed from ESPNcricinfo
and CricTracker match pages for internal analysis; news-derived
facts (signings, coaches) are recorded with their outlet and date in
the files themselves. Where a licence is not known it is stated as
"not recorded", never assumed.

Field note — player_of_match (plan 1.5, resolved 2026-10-29):
player_of_match and player_of_match_id in the canonical matches
table are populated for all 64 S1/S2 matches from the cricsheet
NPL bundle, which carries info.player_of_match for every match.
The stored layer had shipped null 64/64 (it predates the ingest's
capture of the field); populated by
scripts/populate_player_of_match.py using the ingest's own
semantics — first listed name in its raw cricsheet surface form
(e.g. "AK Sah", "BKEL Milantha"), id = "player_" + lowercased name
with underscores. The diff was limited to these two columns and
verified cell-by-cell; canonical-name resolution remains the
identity registry's job, not this column's. (An initial Batch 2
pass retired the field on the inference that the bundle lacked
it; the bundle was then located and checked directly — it carries
the field 64/64 — and the decision was corrected to populate.
See docs/WORKLOG.md, Batch 2 §1.5.)
