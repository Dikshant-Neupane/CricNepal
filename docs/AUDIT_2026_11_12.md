## What the project is, in plain words

A Janakpur Bolts / Nepal Premier League analytics dashboard and
prediction system with three separate prediction systems that are
never pooled:

1. **Pre-match win probability** (frozen, pre-registered): the
   champion is a logistic blend `p = 0.5 * p_elo + 0.5 * p_xi`, scored
   per frozen stage (P0 pre-season, P1 confirmed XI, P2 post-toss)
   plus a simulator shadow series. Frozen by
   `docs/PREREGISTRATION_S3.md` (2026-10-24); a challenger is promoted
   only if it beats the champion on frozen-log log-loss, with the
   checkpoint gate.
2. **In-play win probability**, delivery-level, separate harness.
3. **S3 player-performance / bowler-economy forecasts** for
   recruiting (Ridge/LGBM scripts + the phase-aware forecaster).
   This is the only system this audit changes the modelling of; the
   pre-match system is scored only, never refitted or promoted.

## Experiment B — bowler economy, S1→S2 validation, S2→S3 holdout

Target (stated once, used everywhere): a bowler's overall economy in
the target season, ALL phases, legal balls only
(`extras_type` not in wides/noballs); bowler runs = `runs_off_bat` +
`runs_extras` except byes/legbyes (bowler runs = `runs_off_bat`
only); economy = bowler runs / legal balls × 6. Minimum 12 legal
balls in each season of a pair. Candidates use the prior season only.

**Validation, S1→S2, LOO-CV, n=42 pairs** (target mean 7.67, SD 1.39):

| Candidate | MSE | RMSE | MAE | vs shrink-k60 sq-err 95% CI |
|---|---|---|---|---|
| RTM 50/50 | 1.619 | 1.273 | 1.052 | -0.189, CI [-0.369, -0.015] — excludes zero |
| Shrinkage k=30 | 1.793 | 1.339 | 1.119 | -0.016, CI includes zero |
| Shrinkage k=60 | 1.808 | 1.345 | 1.119 | — |
| Shrinkage k=150 | 1.874 | 1.369 | 1.103 | +0.065, CI includes zero |
| League mean (S1) | 2.198 | 1.483 | 1.181 | +0.389, CI includes zero |
| Ridge, nested-LOO alpha | 2.562 | 1.601 | 1.182 | +0.753, CI includes zero |
| Naive (carry S1) | 2.677 | 1.636 | 1.304 | +0.869, CI includes zero |

**Holdout, S2→S3, evaluated exactly once after selection was frozen
on S1→S2, n=35 pairs** (target mean 7.82, SD 2.61; S3 is partial —
12 ingested matches, median 36 balls per bowler — so target noise is
roughly double the validation set's):

| Candidate | MSE | RMSE | MAE |
|---|---|---|---|
| Naive | 5.356 | 2.314 | 1.875 |
| Ridge (alpha 0.1, frozen) | 5.488 | 2.343 | 1.902 |
| Shrinkage k=30 | 5.378 | 2.319 | 1.937 |
| Shrinkage k=60 | 5.496 | 2.344 | 1.937 |
| RTM 50/50 | 5.594 | 2.365 | 1.952 |
| Shrinkage k=150 | 5.811 | 2.411 | 1.975 |
| League mean (S2) | 6.879 | 2.623 | 2.139 |

Every holdout paired-bootstrap CI vs shrinkage-k60 includes zero.

**Verified conclusion.** RTM's validation edge does not replicate on
the fresh holdout (it ranks 4th of 6 there); Ridge is worst on
validation and ties shrinkage on the holdout; k in [30, 150] is
indistinguishable on both evaluations. At these N, model choice does
not matter — sample noise dominates. The best VERIFIED predictor is
therefore the simplest near-best on both evaluations: **the shrinkage
estimator (k=60, the live forecaster's constant)**. Ridge does not
beat shrinkage on either evaluation, so per the project's own rule
("model MUST beat shrinkage to be included") Ridge stays out of the
headline predictions — and the fixed `ridge_primary_model.py` now
enforces that itself (it falls back to shrinkage when Ridge loses,
which it does: LOO MSE 2.789 vs shrinkage 1.660, n=42, on the
corrected target). No new model is shipped; the improvement is a
corrected target, corrected baselines, and a verified selection.

The fixed Ridge pipeline run end to end from a fresh clone
(`prepare_season_features.py` → `prepare_features_extended.py` →
`ridge_primary_model.py`): n=42 paired, baselines naive 2.677 /
RTM 1.437 / shrinkage 1.660, Ridge LOO 2.789, best alpha 0.01.
Final S3 predictions (83 bowlers) are shrinkage-based on every row.
The two implementations of the target definition (audit script vs
fixed `prepare_season_features.py`) agree exactly: max |diff| 0.0
over 223 matched bowler-seasons.

## Findings and fixes (A1–A10)

All ten have a failing-before / passing-after test in
`tests/test_audit_2026_11_12.py` (10 tests) plus the updated
`tests/test_phase_shrinkage.py` comments.

- **A1 — Middle overs excluded from "overall economy".**
  `scripts/prepare_season_features.py` aggregated only powerplay +
  death; `scripts/ridge_primary_model.py::_season_agg` set
  `total_balls = pp_balls + dth_balls`. Middle is 8,145 of 17,553
  balls (46%). Fixed: middle aggregated everywhere; `_season_agg`
  now totals all three phases; `feat_cols` gains the three middle
  features. This changes the target definition; it is documented in
  the scripts, in this note, and in the Ridge report.
- **A2 — Leaky column in the training frame.**
  `ridge_primary_model.py::build_paired_dataset` carried
  `"s1_econ_trend": r2["raw_economy"] - r1["raw_economy"]` — the S2
  target as a feature. It was not in `feat_cols`, but a leaky column
  in the frame is a trap. Removed.
- **A3 — S3 feature mapping sent 3 of 9 features to 0.0.**
  The S3 loop built feature names with `fc.replace("s1_", "s2_")`
  (`s2_economy`, `s2_sos_econ`, `s2_balls`), but the S2 aggregate
  frame has `raw_economy`, `sos_adj_economy`, `total_balls`. So
  `s1_economy`, `s1_sos_econ` and `s1_balls` — the three most
  important features — were 0.0 in every S3 Ridge prediction, and
  the same bug existed in the per-bowler explanation loop. Fixed
  with an explicit `S2_FEATURE_MAP` + `s2_feature_vector()`, used by
  both loops. Verified: Ridge S3 predictions now span 5.46–9.74 and
  differ from shrinkage on every row (previously degenerate).
- **A4 — Baselines used the target season's league mean.**
  `main()` set `league_avg` from S2 (`season_norm == 2`) and used it
  for the S1→S2 RTM/shrinkage baselines — target-season information
  in the baseline. Fixed: `prior_season_league_mean()`; baselines
  and the comparison table use the S1 mean (7.908), S3 predictions
  use the S2 mean (7.849).
- **A5 — Extended features dropped middle too.**
  `scripts/prepare_features_extended.py::weighted_econ` combined only
  powerplay + death. Fixed: all three phases, skipping phases with
  no balls or NaN economy.
- **A6 — Missing phase economy filled with 0.0.**
  `prepare_season_features.py` did `merged.fillna(0)`, so a bowler
  who never bowled death got `death_econ = 0.0` — a perfect economy.
  Fixed: balls/dot% fill 0, economies stay NaN. (79 of 251 rows have
  NaN death economy; 25 have NaN middle economy.)
- **A7 — Fresh-clone dead paths.**
  `data/normalized/ball_by_ball_normalized.parquet` is not in the
  repo (only 6 parquet files are tracked under `data/`), yet ~15
  modules read it, and the full test suite could not even collect
  (1 collection error, 0 tests run). Fixed with the fallback the
  dashboard loaders already use: normalized file if present, else
  the shipped `data/final/parquet/ball_by_ball.parquet`, logged, in
  `scripts/build_tu_par_tables.py::load()` and
  `scripts/prepare_season_features.py` (`resolve_ball_parquet()` /
  `resolve_matches_parquet()`). The TU par-table pins still hold
  under the fallback, which also evidences that the final parquet
  matches the normalized layer for those tables.
- **A8 — Phase priors did not reproduce.**
  `src/analytics/s3_performance_forecaster.py` claimed Powerplay
  6.87 / Middle 7.02 / Death 9.12, "computed from S1+S2, legal
  deliveries only". Recomputed from the shipped S1+S2 data under the
  implemented definition (wides/no-ball rows dropped, runs_total /
  rows × 6): 6.56 / 6.81 / 8.79 (14,464 rows). The old constants
  matched neither that definition nor the proper legal-ball
  definition (6.73 / 6.92 / 8.89). Fixed to 6.56 / 6.81 / 8.79 with
  the definition stated in the comment, and pinned by a test that
  recomputes them from the shipped data (tolerance 0.05) — the old
  test comments still said 6.65, i.e. the priors had drifted before
  without any test noticing. Known caveat recorded in the comment:
  the implemented definition also drops wide/no-ball runs from the
  numerator, understating true bowler economy by ~0.1–0.2; switching
  definitions is a separate, tested change, not done here.
- **A9 — LightGBM tuned on n≈37 and could not even be imported.**
  `scripts/train_model_lgbm.py` ran `RandomizedSearchCV` (20 iters,
  7 hyperparameters) on n≈37–46, then refit the tuned model per
  fold and reported that as CV MSE (optimistically biased), and
  imported `lightgbm` at module level although it is not in
  `requirements.txt`. Fixed: lazy import after a hard guard —
  refuses below n=100, points at the Ridge script, and the biased
  manual CV is flagged in a comment for replacement by nested CV
  before any use at n≥100. Verified: the guard fires at n=46.
- **A10 — Coin note hardcoded S2.**
  `src/prediction/metrics.py::coin_baseline_metrics` said "(S2:
  0.34375)" in its note, wrong on any other season's data. Made
  season-neutral. The F2 history stays documented in
  `docs/PREDICTION_SYSTEM.md` and `tests/test_audit_fixes_f1_f3.py`.
